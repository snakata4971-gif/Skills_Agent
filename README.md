# QA Skill Builder

ベテランの検品ノウハウを「スキル」として作り、蓄え、AIエージェントと作業者が同じ基準で検品できるようにする仕組みの**試作版（MVP）**です。
検品結果の記録、顧客への確認、実績からのスキル改善までを1つのアプリで試せます。

| 部品 | 画面 | できること |
|---|---|---|
| ① スキルビルダー | スキルビルダー | POPの写真・手順書（PDF）・作業動画・メモから、AIがスキルの下書きとベテランへの質問を作る。回答すると下書きに反映される |
| ② スキルライブラリー | スキルライブラリー | スキルを版で管理する（下書き → 承認 → 公開、差分、前の版に戻す）。納品IDのスキャンで、共通・カテゴリ別・顧客別のスキルを自動で引き当てる |
| ③ 検品エージェント | 検品・顧客確認 | 顧客写真と現物写真を比較して判定し、WMSに登録する。NGなら確認メールの作成 → 顧客の回答 → 処理（過不足待ち・返品・廃棄・そのまま出荷）まで進める |
| ④ 学習・改善 | 学習・改善 | 人がAIと違う判断をした理由、AIが迷った点、WMS操作エラーから改善案を作り、過去の検品でテストして公開する |

作業者の担当は「スキャン・開梱・撮影・確定」です。判定・WMS登録・メール作成・返信の読み取り・処理の実行はアプリが行います。
返品・廃棄など取り消せない処理や、メールの送信、スキルの公開は、必ず人が承認します。

## すぐに試す（デモモード）

### 必要なもの
- Node.js 22.13 以上（https://nodejs.org/）
- Google Chrome（WMSの「ブラウザ自動操作モード」を使う場合のみ）

### 起動
- Mac：`start.command` をダブルクリック
- Windows：`start.bat` をダブルクリック
- ターミナルから：

```bash
npm install
```

```bash
npm start
```

起動したらブラウザで http://localhost:3000 を開きます。最初の画面「はじめに」にデモの進め方が書いてあります。
止めるときは、起動したウィンドウで Ctrl + C を押します。

APIキーを設定していない間は**デモモード**で動きます。AIの代わりに「模擬判定」を使い、同梱のサンプル写真には用意した判定結果を返します（それ以外の写真は「要確認」として人に回します）。画面の流れはすべて試せます。

### サンプルの納品（同梱の模擬WMSに登録済み）

| 納品ID | 顧客 | カテゴリ | 内容 | 想定される判定 |
|---|---|---|---|---|
| N-260923-001 | C-1001 | トレカ | 問題なし | OK |
| N-260923-002 | C-1003 | トレカ | 枚数不足（3枚 → 2枚） | NG |
| N-260923-003 | C-1004 | トレカ | 折れと白欠け | NG |
| N-260923-004 | C-1005 | アパレル | 色違い（紺 → 赤） | NG |
| N-260923-005 | C-1006 | アパレル | 問題なし | OK |
| N-260923-006 | C-1002 | おもちゃ | 箱の角つぶれ（顧客別ルールでNG） | NG |
| N-260923-007 | C-1007 | おもちゃ | 問題なし | OK |
| N-260923-008 | C-1008 | スニーカー | 専用スキルなし → 作成依頼 | 要確認 |
| N-260923-009 | C-1001 | アパレル | 問題なし（同じ顧客の2件目） | OK |

顧客ID（例: C-1001）をスキャンすると、その顧客の納品を選ぶ画面になります。現物写真は検品画面の「サンプル写真を使う（デモ）」で追加できます（`samples/現物写真/` にも同じ写真があります）。

## AI（Claude）を接続する

1. `.env.example` をコピーして `.env` という名前にする
2. `ANTHROPIC_API_KEY=` の後ろにAPIキーを書く
3. アプリを再起動する（右上の表示が「AI接続中」になります）

| 設定 | 既定値 | 説明 |
|---|---|---|
| `QA_MODEL` | `claude-opus-5` | 使うモデル。画面の「設定」でも変更できます |
| `QA_EFFORT` | `high` | 推論の深さ（low / medium / high / xhigh / max）。低いほど速く安い |
| `QA_IMAGE_MAX_PX` | `1280` | AIに送る写真の長辺のピクセル数。大きいほど細部が見えるが費用が上がる |

AIを接続すると、次の処理が実際のAIで動きます：写真の比較判定、スキルの下書きと質問の作成、確認メールの作成、返信メールの読み取り、スキルの改善案、WMS画面の変化に合わせた操作スキルの修正案、専用スキルがない商品のスキル選定。

### 費用の目安（必ずPoCで実測してください）
判定1件あたりの費用は、写真の枚数・大きさ・モデル・推論の深さで大きく変わります。
写真4〜5枚（長辺1280px）、スキルの文章はキャッシュが効く、1ドル150円という前提でのおおよその目安は次のとおりです。

| モデル | 1件あたり（目安） | 1日4,000件なら（目安） |
|---|---|---|
| claude-opus-5 | 10〜20円前後 | 4〜9万円前後 |
| claude-sonnet-5 | 4〜9円前後 | 1.5〜3.5万円前後 |

実際の使用量は「学習・改善」画面の「AIの利用量（概算）」で確認できます。モデルや推論の深さは、精度（特に見逃し率）と費用を実測して決めてください。

## WMSとの連携

「設定」画面で連携方法を切り替えられます。どちらの方法でも、検品画面や処理の流れは同じです。

### 1. API連携（本番の想定）
WMSのAPIで、納品情報と顧客写真の読み取り、検品結果・ステータス・証跡写真の登録を行います。
WMS側に次のAPIを用意してもらうか、既存のAPIに合わせて `src/wms/apiAdapter.ts` を書き換えます（アプリの他の部分は変更不要です）。

接続先は `.env` の `WMS_BASE_URL`（例: `https://wms.example.co.jp`）、認証は `X-WMS-API-Key` ヘッダー（`WMS_API_KEY`）です。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/lookup?code={顧客IDまたは納品ID}` | スキャンしたIDから顧客と検品待ちの納品を返す |
| GET | `/api/shipments/{納品ID}` | 納品の詳細（申告内容・顧客写真のURL・ステータス） |
| POST | `/api/shipments/{納品ID}/inspection` | 検品結果を登録。`{"result": "OK" \| "NG" \| "保留", "note": "…", "inspector": "…"}` |
| POST | `/api/shipments/{納品ID}/status` | ステータスを更新。`{"status": "返品手配中", "note": "…"}` |
| POST | `/api/shipments/{納品ID}/evidence` | 現物写真（証跡）を登録。`multipart/form-data` の `files` |
| GET | `/api/health` | 接続確認 |

`GET /api/shipments/{納品ID}` の応答例：

```json
{
  "id": "N-260923-004",
  "customer": { "id": "C-1005", "name": "セレクトショップD", "email": "c1005@example.com" },
  "category": "アパレル",
  "declared_value": 8900,
  "status": "入荷済み（検品待ち）",
  "items": [{ "name": "ロゴTシャツ", "qty": 1, "color": "ネイビー", "size": "M", "note": "新品・下げ札付き" }],
  "customer_photos": [{ "url": "https://wms.example.co.jp/files/customer/N-260923-004-1.jpg" }],
  "evidence_photos": [],
  "inspection": null
}
```

同梱の模擬WMS（http://localhost:3000/wms/ ）がこの仕様どおりに動くので、WMSベンダーとの確認に使えます。

### 2. ブラウザ自動操作（APIがない場合の代替）
WMSのWeb画面を、決まったスクリプトで操作します（AIが画面を見てクリックする方式ではないため、速く確実です）。
どの画面要素を操作するかは、操作スキル `operation/wms-browser-operation` のセレクター表に書かれています。

- WMSの画面が変わって操作に失敗すると、見つからなかった要素と画面の状態が記録されます
- 「学習・改善」の「操作スキルの修正案を作る」で、改善エージェントが画面を確認しながらセレクターを直し（最大4回）、読み取りだけのテストで確認します
- 承認して公開すると、次の操作から新しいセレクターが使われます

模擬WMSの管理画面（http://localhost:3000/wms/admin ）で画面バージョンを「2.0」にすると、画面リニューアルで自動操作が止まり、修正案で復旧する流れを試せます。

実際のWMSで使う場合は、ログイン手順の追加と、ログイン情報の安全な保管が必要です（試作版の模擬WMSにはログインがありません）。

## 画面の使い方（概要）

- **検品**：顧客IDまたは納品IDをスキャン（入力してEnter）→ 撮影チェックリストに沿って撮影 →「AI照合を開始」→ 判定を見て OK / NG / 保留 で確定。AIと違う結果にするときは理由を書きます（スキル改善に使われます）。判定を待たずに次の商品をスキャンでき、右側のキューで確認待ちの検品が分かります
- **顧客確認**：NGの検品ごとにケースができます。確認メールの下書き → 承認して送信（試作版は模擬送信）→ 顧客が回答ページで対応方法を選ぶ → 対応を確定 → （返品・廃棄は責任者が承認）→ 処理を実行すると、WMSのステータス更新と作業者への指示が出ます
- **スキルライブラリー**：スキルの内容・版の履歴・差分の確認、手での編集（下書き保存）、承認、前の版への戻し、廃止。「引き当てテスト」で、どのスキルが使われるかを確認できます
- **スキルビルダー**：資料をまとめてドロップ → 中身を確認して資料ごとに説明を付ける →「AIで下書きを作る」→ 質問に回答 → ライブラリーに下書き保存 → ライブラリーで承認。スキルの名前と対象カテゴリはAIが資料から提案します（「名前・対象を編集」で変更可）。専用スキルがなかった商品は「作成依頼」として届きます
- **学習・改善**：一致率・見逃し・過検出の集計、学習材料、AIが迷った点、WMS操作エラー、改善案（差分・テスト・承認）、AIの利用量
- **設定**：担当者名、モデル、並走運用、自動OKの条件、WMSの連携方法、デモデータの初期化

### スキルビルダーに入れられる資料

| 資料 | 形式 | AIへの渡し方 |
|---|---|---|
| 写真（POP・掲示物・作業場面・商品） | JPG・PNG・WebP・GIF・TIFF・HEIC（iPhone） | 向きを直したJPEGにして渡す |
| 作業動画（検品の手元・端末の操作画面） | MP4・MOV・M4V・WebM・AVI・MKV・WMV など | 最初のコマと場面が変わったところ（最大16コマ）を時刻つきで切り出して渡す。音声は読み取らないため、補足は説明欄かメモに書く |
| 手順書・マニュアル | PDF | そのまま渡す（合計12MBを超える分は Files API で別送。1日で自動削除） |
| 手順書 | Word（.docx） | 本文・箇条書き・表を文章で、文書内の図を画像で渡す |
| チェック表 | Excel（.xlsx） | シートごとにタブ区切りの表で、図を画像で渡す |
| 研修資料 | PowerPoint（.pptx） | スライドごとの文章と発表者ノート、スライドの画像を渡す |
| メモ・一覧 | テキスト・Markdown・CSV（UTF-8 / Shift_JIS） | 文章として渡す |

- 1ファイル1GBまで、一度に20ファイルまで。動画のコマの切り出しには ffmpeg が必要です
- 古い形式（.doc / .xls / .ppt）は読めないため、.docx / .xlsx / .pptx か PDF に保存し直してください
- 写真・動画のコマ・文書内の図は、1回あたり合計80枚までAIに渡します（多い場合は動画のコマと文書内の図を均等に間引きます）
- アップロード後、資料をクリックすると「AIに渡す内容」（動画のコマ、文書から取り出した文章と図）を確認できます

### 並走運用と自動OK
導入初期は「並走運用」をONにしておき、AIの判定は参考表示だけにして、必ず人が確定します。人との一致率と見逃し率を確認してからOFFにすると、次の条件をすべて満たすOK判定だけが自動で確定されます：AIの総合判定がOK、すべての判定項目の確信度が基準以上、申告額が高額品の基準未満。NGや要確認は常に人が確認します。

## スキルの形式

スキルは Anthropic の Agent Skills と同じ `SKILL.md` 形式（先頭に設定、続けて本文）です。アプリ独自の設定は `metadata` の中に書きます。

```markdown
---
name: trading-cards
description: トレーディングカード（トレカ）の検品。カード名・カード番号・レアリティ・枚数・状態…を確認する。
metadata:
  layer: category          # common / category / customer / operation / communication / disposition
  title: トレカ検品
  version: 1.0.0
  owner: トレカ担当リーダー
  applies_to:
    categories: ["トレカ", "トレーディングカード", "カード"]
---
# トレカ検品

## 撮影指示          ← 検品画面の撮影チェックリストになる
- カードの表面（1枚ずつ、カード番号とレアリティ表記が読めるように）

## 判定項目と基準     ← AIの判定基準
### カードの一致（最重要）
- カード名・カード番号・レアリティ表記が顧客写真と一致するか。…
```

| 種類（layer） | 使われ方 |
|---|---|
| common（共通） | すべての検品に適用 |
| category（カテゴリ別） | `applies_to.categories` と納品のカテゴリが一致すると適用 |
| customer（顧客別） | `applies_to.customers` の顧客に適用。共通・カテゴリより優先 |
| communication（連絡） | 確認メールの書き方 |
| disposition（処理） | 返信後の処理。`requires_approval`（承認の要否）・`wms_status`・`worker_instruction` を持つ |
| operation（端末・システム操作） | WMS画面の自動操作の手順とセレクター |

- 承認済みのスキルは `skills/` フォルダに書き出されます（Agent Skills として他のツールでも読めます）
- 初期スキルの原本は `seed/skills/` にあります
- `skills/` にフォルダごと置いたスキルは、起動時にライブラリーへ取り込まれます

## 仕組み

- **判断はAI、操作は決まったスクリプト**：写真の比較やメール・返信の読み取りはAIが行い、WMSへの登録はAPIか決まったスクリプトで行います。AIの出力は形式（JSONスキーマ）を指定して受け取り、想定外の値は「要確認」として人に回します
- **スキルは引き当てる**：スキャンした顧客IDとカテゴリで確定的に選びます。カテゴリが一致しないときだけ、キーワード（AI接続時はAIがカタログから選定）で近いスキルを探し、なければ作成依頼を登録します
- **学習は承認制**：改善案は必ず差分とテストを確認してから、人が承認して公開します。どの検品にどの版のスキルを使ったかが記録されるため、クレーム時に当時の基準を説明できます
- **安全ルール**：項目にNGがあれば総合もNG、問題の記載があればOKにしない、見逃しを最も重い失敗として扱う、取り消せない処理は承認必須

### フォルダ構成
```
src/
  server.ts, app.ts        起動とWebアプリの組み立て
  ai/                      Claude の呼び出し（判定・スキル作成・メール・改善案・スキル選定）と、デモ用の代替
  skills/                  スキルの形式・ライブラリー（版管理）・引き当て
  wms/                     WMS連携（API / ブラウザ自動操作）と模擬WMS（mock/）
  inspections.ts           検品の流れ（撮影・判定・確定・WMS登録）
  cases.ts                 顧客確認の流れ（メール・回答・承認・処理）
  learning.ts              集計・学習材料・改善案とテスト
  builderService.ts        スキルビルダー（資料・動画のコマ切り出し・下書き・質問）
  routes/                  画面から呼ぶAPI・顧客の回答ページ
public/                    画面（HTML / CSS / JavaScript）
seed/                      初期スキルの原本・サンプル画像・デモ用の判定結果
samples/現物写真/           デモで使う現物写真
skills/                    承認済みスキルの書き出し先（自動生成）
data/                      データベースとアップロードされた写真（自動生成）
tests/                     自動テスト
```

### データの保存と初期化
データはすべて `data/` フォルダ（SQLite と写真）に保存されます。最初の状態に戻すには、「設定」→「デモデータを初期化」を使うか、アプリを止めて `data/` と `skills/` を削除します。

## 本番運用に向けて（この試作版で対応していないこと）

- ログインと権限（作業者・ベテラン・責任者の役割、SSO）
- HTTPS（`localhost` 以外のパソコンからカメラを使うにはHTTPSが必要です）
- 実際のメール送信と、返信メールの自動取り込み
- 顧客向け回答ページのインターネット公開（有効期限付きURLなど）
- 本番用のデータベース・写真の保管先・処理の順番待ち（キュー）
- 写真や顧客情報の保存期間・アクセス管理
- 1日4,000件規模での負荷試験と、AIの利用上限（レート制限）の確認
- 実際のWMSとの接続（API仕様の合意、またはログインを含む操作スキルの作成）
- 顧客のパソコンに常駐するアプリ版

## 次の一歩（PoCの進め方の例）
1. `.env` にAPIキーを設定し、模擬WMSの「入荷を登録（テスト用）」で実際の商品写真（トレカ・アパレル・おもちゃ）を使って判定精度を確かめる
2. 現場の作業手順POPの写真をスキルビルダーに入れて、自社のスキルを作る
3. 並走運用で、人との一致率と見逃し率を数週間測る
4. WMSベンダーと上記のAPI仕様をすり合わせる（難しければブラウザ自動操作で始める）

## 困ったとき

| 症状 | 対処 |
|---|---|
| 「ポート 3000 は使用中です」と出る | すでに起動していないか確認する。別のポートを使う場合は `.env` の `PORT` と `APP_BASE_URL` と `WMS_BASE_URL` を変更 |
| 右上が「デモモード」のまま | `.env` の `ANTHROPIC_API_KEY` を確認し、アプリを再起動 |
| 「APIキーが無効です」と出る | APIキーを確認（前後の空白・改行に注意） |
| ブラウザ自動操作で「Chromeを起動できません」 | Google Chrome をインストールするか、`.env` の `CHROME_PATH` にChromeの場所を書く |
| カメラが起動しない | ブラウザのカメラ許可を確認。`localhost` 以外で開く場合はHTTPSが必要。写真ファイルの追加でも検品できます |
| 動画をアップロードできない | 動画からコマを切り出すには ffmpeg が必要です（Mac: `brew install ffmpeg`）。ない場合は場面ごとの写真をアップロードしてください |
| Word・Excel・PowerPoint が「読み込めません」になる | 古い形式（.doc / .xls / .ppt）やパスワード付きのファイルは読めません。新しい形式か PDF で保存し直してください |
